# 启动与交互性能

编辑器使用共享的 Patchwork 文本模型，同时保留持久化、外部更新、本地撤销隔离、空格命令和统一排版。本文记录现有性能策略及测量方法。

## 设计与实现

| 开销来源                    | 当前策略                                                                                                                              | 保留的行为                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 递归文件监听初始化          | 目录监听深度为 0，排除隐藏和生成路径；访问过的目录中的文本事件刷新选择器。显式打开的笔记，包括隐藏笔记，单独监听。                    | 已打开文件的外部编辑、替换和删除仍可观察。                                                 |
| 窗口进程中的 Automerge 同步 | 现有 Workspace、Repo 和文件桥接运行在一个 Node 工作线程中；Comlink 提供类型化 RPC，主线程转发官方 MessageChannel 同步消息。           | CRDT 和数据结构不变；精确文档头确认、持久化、文件校验和正常退出仍使用原有 Workspace 方法。 |
| 启动时加载模块              | 轻量启动模块先显示界面；插件在 `manifest.ts` 中声明元数据，动态加载实现，只导入启用的插件及其依赖。                                   | 核心层仍负责注册表校验、依赖顺序、命令归属和清理。                                         |
| 界面线程解析 Markdown       | 按需启动应用级工作线程，运行现有 remark/GFM/数学解析器；实时编辑使用 70 毫秒防抖，同一源码的请求共享待完成解析。                      | CodeMirror 仍是文本模型；解析只改变显示。                                                  |
| 源码模式的解析              | 源码编辑只使语法缓存失效，不主动解析；实时视图或明确的 Markdown 命令才请求语法树。                                                    | 源码模式中的链接和任务命令仍可用，并遵守输入法组词和只读状态。                             |
| 重复生成装饰和组件          | 使用原生 RangeSet 索引激活区域；光标在同一区域移动时复用装饰，源码未变化的组件保留 DOM。                                              | 当前元素显示源码；映射后的任务组件仍能找到最新文档位置。                                   |
| 公式加载与渲染              | 仅在显示公式时加载 KaTeX，异步渲染后请求 CodeMirror 重新测量。                                                                        | 使用 MathML，禁用可信命令，维持统一字号。                                                  |
| 大型文件列表                | 超过 200 项的列表只渲染最多 56 行，并用占位高度维持滚动位置；较小列表在选择变化时复用行。                                             | 保留键盘、鼠标滚动与点击、选中状态、无障碍选项标识和完整目录搜索。                         |
| 预览和搜索 I/O              | 预览请求防抖 60 毫秒，缓存 20 个结果至刷新；最多读取 128000 字节，流式解码并显示最多 32000 字符。搜索扫描当前子树，共享进行中的扫描。 | 保留 UTF-8 边界和文件路径限制，旧响应不能覆盖新选择。                                      |
| 重复配置与保存              | 相同设置跳过重新配置；合并已排队的持久化请求，不额外增加保存延迟。                                                                    | 文件和目录的 fsync、投影日志及退出时的精确文档头确认保留。                                 |
| 开发启动时重复构建          | `pnpm dev` 比较构建输入的内容指纹，未变化时复用产物。                                                                                 | `pnpm build` 仍执行完整检查和构建，`pnpm start` 直接启动现有产物。                         |

CPU 采样曾发现 Electron 主线程的 `receiveSyncMessage` 会造成首次输入停顿。将现有数据服务移入 Node 工作线程后，计算不再占用窗口和 IPC 分发线程。适配方式参考上游 [Comlink Node 工作线程示例](https://github.com/GoogleChromeLabs/comlink/blob/main/docs/examples/06-node-example/main.mjs)，没有引入自定义 RPC 协议或替代 CRDT。

Markdown 没有另行实现增量语法。编辑暂停后仍在工作线程中完整解析；解析期间，未受影响的装饰随 CodeMirror 变更映射，活动行显示源码。只有结果对应的文档仍为当前文档时才应用结果。禁用插件会终止工作线程并拒绝待完成请求；关闭缓冲区会使其待完成显示工作失效。

工作线程构建使用上游字符实体解码器的默认实现，因为其浏览器专用实现依赖 `document`。文本语法高亮只将语言目录作为元数据导入，使用 `LanguageDescription.load()` 按需加载所选语法；缓冲区在本地 Compartment 中使用原生增量解析器或上游流模式。切换语言、关闭或重新配置缓冲区后，过期加载结果不会生效。未知文件不加载语法，Nix 使用独立的按需语言描述符。

## PDF 和图片资源策略

媒体插件声明格式时不导入 PDF.js；启用时加载控制器，打开 PDF 时才加载 PDF 库及专用工作线程。图片使用原生解码。非文本缓冲区不创建 CodeMirror 视图或 Automerge 文档，但启动应用时仍会初始化共享数据工作线程、渲染端 Repo 和空编辑器基础设施。

PDF 通过经过校验的本地 URL 和 PDF.js 公共传输接口按 65536 字节分段读取。协议层将 Electron 文件加载器的部分响应规范化为 206，并提供 `Content-Range` 和 `Accept-Ranges`。销毁视图会取消请求与渲染，过期结果不能覆盖当前内容。

只栅格化当前页，默认画布预算为 16000000 像素，最长边为 16384 像素；逻辑缩放可以高于栅格分辨率。该限制只约束页面画布，不限制整个进程的内存。

隐藏 PDF 视图会释放页面画布，但保留已加载文档和工作线程；关闭或禁用时释放它们。同目录图片导航会替换当前图片槽，显式按路径打开的文件可以保留独立缓冲区。资源监听使用引用计数，并保留其他使用方需要的目录监听。元数据预览不会加载 PDF.js 或解码图片。

PDF 文本搜索按需顺序扫描，最多保留 200 条匹配，并限制进度界面的更新频率；大纲最多保留 1000 项。这些上限不构成对 PDF 大小、页数、搜索延迟或图片解码内存的通用保证。配置见[媒体查看器参考](plugins.md#媒体查看器)。

## 可复现的测量

```sh
pnpm bench current
```

该命令先构建当前源码，再在 Xvfb 中运行 `scripts/benchmark.mjs`。如需测量现有构建而不重新构建：

```sh
xvfb-run -a -s '-screen 0 1280x900x24' node scripts/benchmark.mjs current
```

隔离夹具包含 4800 个生成的依赖文件、1201 篇 Markdown 笔记，以及一篇 52180 字节的富格式 Markdown 笔记。目录和笔记场景分别启动三次，每次使用新的应用配置和 CRDT 存储。笔记就绪表示文件已经可编辑，异步的视觉渲染可能稍后完成。采样交互前会等待 1.5 秒。

目录场景发送 40 次导航按键并等待下一动画帧；笔记场景通过 Playwright 输入 12 个字符并等待动画帧。历史字段 `p95Ms` 在目录场景中保存排序后 40 个样本的索引 38，在笔记场景中保存 12 个样本的最慢值；应将其视为偏高的样本值，而非总体百分位数。

墙钟延迟包含自动化协议调度、编辑器处理和渲染，不是单一 JavaScript 函数的耗时，也不代表所有机器。原生 Wayland/GPU 行为以及已有大型 CRDT 历史需要单独测量；脚本不会清空操作系统缓存。

`fileWatchHandles` 只统计浏览器主线程可见的句柄，工作线程中的句柄不计入，不能当作应用监听总数。`mainCpuAfterReadyMs` 来自 `process.cpuUsage`，包含浏览器进程内所有线程，包括数据工作线程。

原始结果写入 `artifacts/performance-<label>.json`。设置 `PORTLEAF_CPU_PROFILE=1` 可记录渲染进程和主进程 CPU 采样；设置 `PORTLEAF_BENCH_RUNS=1` 可缩短诊断运行。性能采样使用隔离临时笔记，不接触真实文档。

## 生命周期测量与后续工作

```sh
PORTLEAF_BENCH_LIFECYCLE=40 pnpm bench current
```

此选项在反复打开、关闭文件时采样后端会话、缓存文档、目录监听、渲染视图数量和浏览器 RSS。对比结果时应使用相同环境并记录源码和构建身份。文档不维护历史耗时或体积表，应针对待审查源码重新生成报告。

后续可研究仅查看媒体时延迟初始化文本服务、减少重复 Automerge WASM 资源、独立分发插件，以及建立内存和延迟预算。运行时按需加载不会减少安装资源；关闭视图也不意味着整个进程具有通用内存上限。

## 验证范围与限制

组件与集成测试覆盖浅层监听、已打开隐藏文件的更新、限定范围的搜索、受限 UTF-8 预览、按需导入的去重和重试、过期解析结果、源码模式解析、组件复用和待完成工作线程清理。Electron 场景覆盖真实工作线程渲染、长文档编辑与撤销、渲染期间关闭和重新打开、插件启停、大列表键鼠操作、自动保存、外部修改、输入法组词与统一字体网格。另有原生工作线程退出测试和 SIGKILL 后恢复测试。

启动和编辑仍需要 Automerge WASM、渲染进程与数据工作线程的两份本地文档副本，以及持久磁盘写入。解析移到工作线程只改变 CPU 工作的位置，并不会消除计算。递归搜索仍是按需文件系统扫描，而非持续维护的项目索引；监听范围限于已访问目录和已打开文件，未访问子树在搜索时扫描。当前没有对任意大文件建立统一的大小或延迟保证。
